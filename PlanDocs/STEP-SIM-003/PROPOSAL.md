# 提案

**STEP-SIM-003 · 第 3 轮 · 2026-11-18 · 提案方 Codex**

## 要决定的问题

客户希望用一套简单的 Demo 演示真实的 STEP 相似检索。历史库预置几十个 STEP 文件，用户在界面上传一个新 STEP 后自动触发比对，页面显示候选和比对结果，最好能直接查看两个模型。用户偏好 HTML 界面。

本轮需决定本地 Web 是否作为交付形态、首版三维对比做到什么程度，以及用哪些可重复的样例确认上传、比对和显示串联成功。

## 建议决定

选用**本地 Web Demo**。在一台演示电脑运行服务，由浏览器打开一个页面。页面集中提供上传、比对进度、候选列表和三维查看。前端资源随 Demo 一起部署，现场运行可在断网环境中验证。

| 部分 | 首版拟交付 |
| --- | --- |
| 历史库 | 选一个代表性零件族，建议预置 30–50 个 STEP 文件，优先支持闭合单实体零件。SQLite 保存原始文件、模型标识、文件名和可得的料号及修订。缺少修订时标为「未知」。自制件在库列表、查询或候选页的对应记录以及演示说明中标为「演示样例」。批量导入时预计算尺寸、面积、适用的体积和 GLB 预览。查询文件和历史件独立管理。 |
| 上传与比对 | 通过 HTML 页面上传 .step 或 .stp 后自动发起查询。Python/FastAPI 接收文件并返回查询编号，由本地后台任务用 OCCT 读取和检查几何，统一至真实毫米尺度。页面按查询编号轮询，显示解析中、比对中、完成及失败，失败时给出原因或诊断信息。结果和模型随查询编号关联，避免显示上一轮的数据。 |
| 候选排序 | 对全库用与姿态无关的尺寸和整体几何特征初筛，对入围候选做刚体对齐和双向表面距离计算。用开发样例确定入围数量 K 和排序参数。页面最多展示前 5 个满足对齐检查的几何候选，数量不足时按实际返回。每条展示模型标识、已知修订、整体尺寸差和双向偏差摘要。对齐待复核的候选另列。 |
| 双模型查看 | HTML/CSS/JavaScript 与 Three.js 加载两份 GLB。默认左右并排，联动旋转、缩放和视角。可切换到同坐标双色叠加、调透明度或单独隐藏任一模型。点击候选时，模型和比对数据一起更新。Three.js 和附加加载器随 Demo 提供。 |
| 对齐与差异 | 每次查询对每个进入精排的候选执行多初值刚体对齐和歧义判断。比对只允许旋转和平移，叠加使用同一对齐结果在浏览器场景坐标中的表示。候选列表展示整体双向偏差摘要。安装板样例在「样例标注」旁另显示孔区局部偏差。偏差以毫米显示，使用网格采样时标明为估算。对齐歧义或失败时只提供并排查看，并注明原因。 |

本轮交付的是定版方案中「提交新件、找回几何候选、查看差异」的演示切片。结果页固定显示「结果仅供几何比对。旧件能否采用，由工程负责人依据工程资料确认。」页面使用「几何候选」和「表面偏差」等术语。正式采用流程依据 STEP-SIM-002 执行。

### 对齐与孔位演示口径

- **坐标与单位。** 后端以毫米计算，设 T 为旧件到查询件的对齐变换，C旧、C新分别为各自计算坐标到浏览器场景坐标的换算，包含实际导出和加载时应用的轴向、长度单位及原点变化。若在浏览器对旧件场景应用对齐，矩阵为 C新 × T × C旧⁻¹。两件使用同一换算 C 时简化为 C × T × C⁻¹。叠加保持共同尺度和原点。用一对包含旋转和平移的非对称同件验证，在两边确认至少三个非共线参考点的位置与已知长度。
- **孔位样例。** 在查询件坐标中预先登记包含改动前后孔位的区域和固定视角。页面提供定位及新旧件切换，在「样例标注」旁显示「孔区最大表面偏差（双向网格采样估算，mm）」。对齐后在同一次双向采样结果中，取起点位于登记孔区的双向表面距离的最大值。页面与彩排通过判定共用这一次计算保存的数值。若任一方向的孔区样本未达冻结的有效采样条件，显示「孔区采样不足」，该项记为未通过。候选列表保留标为「整体」的双向偏差摘要。孔区标注用于展示和核对。
- **对齐歧义。** 每次查询按同一规则处理现场上传和预登记样例。对每个进入精排的候选，由模型几何生成多组初始姿态，求解并去除数值上重复的姿态，再按冻结的双向表面拟合条件筛选。若两个不同姿态均达到拟合条件，且两姿态的相对旋转角或旧件采样点质心变换后的位置差超过对应的冻结阈值，则判为歧义。使用旧件同一质心比较位置差，避免将任意模型原点引起的矩阵平移差当成实际位移。没有姿态达到拟合条件时标为对齐失败。歧义或失败进入待复核，只做并排查看。预登记参考点仅用于彩排核验，不参与姿态生成、拟合或歧义判定。即使程序只返回一个低偏差姿态，参考点对应错误也记为错误对齐。

### 建议的演示检查

开发样例用于选择 K、排序参数、采样规则及拟合与姿态差阈值。正式彩排查询在调参前登记，调参时避开这些查询及其同源派生件。彩排前冻结历史库快照、程序版本和参数，并登记每个样例的目标、已知差异、预计状态与接受范围。若彩排暴露问题，先保留本轮失败和改动记录，再用新版本复跑。演示报告逐例记录结果和耗时。

| 样例 | 建议通过口径 |
| --- | --- |
| 同一零件重新导出或变更姿态 | 上传件单独准备。指定同件能在前 5 中找回，叠加后外形重合，偏差落在样例预定的数值误差范围内。 |
| 安装板局部孔位改动 | 指定历史原型出现在页面前 5。按预设视角定位登记孔区，通过双色叠加或新旧件轮换看见孔位改动。标注旁显示本次采样计算的孔区最大偏差，用同一个值核对预登记的接受范围。 |
| 对齐歧义或失败 | 走普通文件上传入口，用预登记样例核对程序返回的歧义或失败状态，记录满足拟合条件的不同姿态及其姿态差。候选进入待复核，保留并排查看。参考点只在程序出结果后核验。低偏差但对应错误计为错误对齐。 |
| 解析失败 | 上传一份损坏或不支持的文件，页面明确显示失败。本次查询不显示上一轮的候选，历史库仍可继续查询。 |

前两类中预登记了目标历史件的所有查询均纳入演示统计，记录「页面前 5 中出现目标件的查询数 / 登记查询总数」。待复核候选不占前 5 名额。目标仅在待复核区、解析失败或库侧导入失败时，该查询计为未找回。分别记录粗排漏出、精排掉出、对齐失败和错误对齐。找回、对齐与三维展示分别检查。结果适用于该版本和这批演示样例。

## 证据

- **客户要求。** 根据用户转述，客户希望用几十件历史 STEP 演示上传后自动比对并在 UI 展示结果。页面使用 HTML 为用户偏好，双模型展示是本提案建议的首版交付。
- **项目基线。** STEP-SIM-002 已采纳。定版实施方案第 3–5 节区分几何排序、实际工程判据和最终采用结论，为本轮划定演示业务边界。[决定记录](../DECISIONS.md) · [定版实施方案](../../Docs/STEP模型相似检索与历史数据复用实施方案.md)
- **接口能力。** SQLite 支持 BLOB。FastAPI 支持文件上传。OCCT 提供 STEP 读取、单位识别与 GLB 导出接口，导出前须准备三角网格。Three.js 的 GLTFLoader 加载 glTF/GLB，OrbitControls 提供旋转、缩放和平移交互。[SQLite 数据类型](https://sqlite.org/datatype3.html) · [FastAPI 文件上传](https://fastapi.tiangolo.com/tutorial/request-files/) · [OCCT STEP 读取](https://dev.opencascade.org/doc/refman/html/class_s_t_e_p_control___reader.html) · [OCCT GLB 导出](https://dev.opencascade.org/doc/refman/html/class_r_w_gltf___caf_writer.html) · [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) · [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)
- **显示坐标。** glTF 使用右手坐标系，正 Y 为上，长度单位为米。OCCT 的 GLB 写出接口提供坐标系换算。比对与显示使用同一对齐结果时，按实际导出配置换算矩阵。[Khronos glTF 坐标与单位规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units) · [OCCT GLB 导出](https://occt3d.com/dev/doc/refman/html/class_r_w_gltf___caf_writer.html)
- **本地实物。** 在项目根目录递归搜索 .step 和 .stp（含隐藏路径，排除 .git），未找到样本文件。当前已有项目方案及汇报材料，实际导入、排名、对齐效果、耗时和现场部署仍待验证。

## 未核实

| 事项 | 验证方法及影响 |
| --- | --- |
| 实际文件来源、大小、单位和几何类型 | 优先从客户的代表性零件族选 3–5 个样本试导入，记录转换状态、闭合性和单位换算。客户样本未到时可用明确标识的自制样例验证流程，客户文件兼容性待实测。 |
| 粗排能否找回目标件 | 用开发样例比较不同入围范围的效果和耗时。冻结后，在完整演示库上逐项记录预登记目标的粗排位置及最终排名。 |
| 对齐可靠性与小差异可见性 | 用已知位姿、歧义样例和已知孔位改动的模型核对坐标、孔区有效采样条件和待复核分支。记录非共线参考点的核验结果、孔区的本次采样值及页面显示值。对照同一套规则检查普通上传与彩排，记录错误对齐和多初值计算耗时。孔位工程量测需要原始几何和经确认的基准。 |
| 实际等待时间和目标环境 | 在演示电脑上记录上传至结果、候选切换到可操作视图的耗时和失败原因。核对 Python 的 OCCT 绑定、浏览器图形渲染和断网运行后再确认演示准备时间及性能预期。 |

## 建议顺序

1. **先打通开发样本链路。** 取建议 3–5 个代表样本，完成 STEP 解析、多初值原尺度对齐、GLB 生成和浏览器叠加。检查同件旋转及平移后叠加一致、不同合格姿态能触发歧义，以及登记孔区的偏差来自当次采样。
2. **再接历史库和页面。** 批量导入完整演示库，跑通上传、轮询进度、候选排序、候选切换、并排及双色叠加。验证几何比对说明、自制件标识、待复核状态，以及孔区标注旁的统计数值和单位。
3. **冻结后在目标电脑彩排。** 按演示检查逐例验证前 5 找回、孔区局部偏差、解析失败和对齐歧义。用普通上传入口，核对页面和登记的接受范围使用同一次采样数值，核验参考点对应关系，记录结果、耗时与失败原因。确认断网可启动并完成整套操作，再进行客户演示。

## 明确不做

- 自动给出「建议采用」或等效判定，自动识别所有关键特征，执行公差、工况或装配干涉的工程放行。
- 整装配比较、客户 PDM/PLM 接入、多人协作和内网平台部署。
- 正式试点的实现语言、框架和部署形态选型。
- 首版差异热图、带符号材料差异和正式工程报告。首版交付双色叠加与偏差摘要。
- 用演示样例推断正式检索准确率、误推荐风险上界或规模化性能。正式阶段、试点和验收条件沿用 STEP-SIM-002。
