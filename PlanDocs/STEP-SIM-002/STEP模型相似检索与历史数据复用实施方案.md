# STEP 模型相似度判断与旧模型直接替代实施方案

**STEP-SIM-002 · 已采纳 · 2026 年 11 月 18 日**

## 1. 业务目标与交付范围

工程师提交一个新设计的 STEP 模型，从千件级历史库中查找候选。如果有旧件的已发布版本能够满足本次工程要求，经确认后终止推进新模型，按该旧件及对应版本的成熟数据做工程。候选来自已知零件库，采用决定针对本次用途和具体修订。

首期选一个代表性零件族开展离线试点。交付结果是一份针对本次用途的采用报告，指明候选料号、发布修订、功能接口的实测差异、适用工况和结论依据。工程负责人决定采用后，登记新使用位置和后续变更通知对象。

先用几何相似度把千件库缩小到少量候选，再逐件判断旧件能否满足本次工程要求。排名可以使用综合分。直接采用应同时满足关键特征、装配接口、用途要求和成熟版本有效性的必查条件。报告显示「建议采用」「待核定」「不可直接采用」及依据，工程负责人确认采用后，工程以旧件的确切料号和修订版为准。若多个版本合格，显示各自的成熟资料与适用范围，供负责人选定。全部候选都未通过时，新设计继续按原流程推进。

替代有方向。判断的是「这个旧版本是否满足本次要求」。例如，两块外形相同的安装板，只有旧件已经验证过当前要求的载荷，才能用这项验证作为采用依据。新模型用于表达设计意图，也用于几何检索。涉及安装、公差、材料或性能的要求以本次有效图纸、技术文件和工程规则为准。

## 2. 每次查询的替代需求单

提交工程师随新 STEP 填写一张需求单，由工程负责人确认。先用 3–5 个真实设计任务试填，按产品族调整模板。每项填入要求、允许范围及单位、证据来源及版本、对应特征或工程基准。暂缺项登记为「待补」；不适用项由负责人说明原因。需求单编号、修订和新模型文件标识随查询保存。

| 必填内容 | 安装板示例及核对依据 |
| --- | --- |
| 用途、关键特征及接口 | 指明固定或定位用途、基准面、孔组、孔径与孔距、配合方向及允许偏差，关联图纸或经确认的设计要求 |
| 材料、表面处理、载荷与环境 | 记录允许的材料范围、处理要求、载荷方向和使用环境，列出旧件需具备的验证证据 |
| 装配约束及相邻件 | 指明安装方向、禁止侵入的空间、最小间隙和配套件修订，附相邻件或已确认的约束包络 |
| 工程责任及证据来源 | 记录提交人、确认人、有效时间和适用项目，标明旧件必须配套的已发布图纸及成熟资料 |

系统仅对需求单中列明的工程要求作符合性判断，其余模型差异作为提示。必查项待补、基准未确认或装配空间证据不足时，该项保持待核定。正式使用中发现此前未覆盖的功能约束时，负责人修订需求单并重新判定，结论可追溯到当时的输入。

## 3. 相似度的判断维度与反例

| 维度 | 核对什么 | 怎么用于判断 |
| --- | --- | --- |
| 整体尺寸与外形 | 实际毫米尺度下的长宽高、面积、闭合实体体积、长宽比、惯性比、曲面类型分布 | 用于快速粗排和发现同系列件。大小和轮廓接近只能说明值得比对 |
| 对齐后的三维表面 | 在同一姿态下，旧到新、新到旧的表面偏差分布、给定容差内的覆盖率及超差区域 | 精排与差异定位。两个方向分别统计，报告高分位偏差、超差面积和异常位置 |
| 局部结构及内部几何 | 孔、槽、台阶、壁厚、空腔、定位销、密封面。核对数量、位置、方向、尺寸和新增或缺失情况 | 明确关键特征后逐项测量。对小孔、薄壁和内腔做局部验证，以免整体统计掩盖变化 |
| 装配接口与方向 | 安装基准、孔组及孔距、配合尺寸、接触面、螺纹、左右手、与相邻件的间隙和干涉 | 以工程基准对齐。接口超出本次允许范围且无批准的豁免时，判为不可直接采用。对旧件凸出区域逐项检查相邻件或约束包络，缺少有效空间证据时待核定 |
| 工程适用条件 | 材料、热处理、表面处理、公差、载荷、环境和适用工艺等本次必查要求 | 按产品族和用途定义必查项。根据图纸、产品制造信息（PMI）、规范及验证记录核对，缺证据时待核定 |
| 成熟版本与资料 | 具体料号、模型修订、图纸和适用的工艺或检验资料，发布状态和限制 | 采用结果绑定确切版本。共享几何的不同料号分别检查。作废或不适用于本工况的版本不能通过 |

例如，安装板外形和三个安装孔均一致，第四个定位孔相对同一基准偏移 2 mm。旧板仍可能排第一。如果接口允许偏差为 0.2 mm，且没有批准的变更，旧板判为不可直接采用。同样大小的差异若出现在非功能倒角，且仍满足要求，则可以评估采用。此处两组数值只用于示例，现场阈值由客户按用途签认。

### 容易误判的情况

| 难点 | 误判怎么发生 | 方案怎么验证 |
| --- | --- | --- |
| 局部差异被平均掉 | 大面积外壳吻合，小孔偏移、内部通道堵塞、槽深变化，被低平均偏差或高覆盖率掩盖 | 用独立的关键特征检查表和高分位表面误差定位异常，测试新增与删除两个方向 |
| 对称件与镜像件 | 最佳拟合把同形的孔组对错，或镜像后表面贴合但配合方向相反 | 用真实手性和基准系验证。测试旋转对称、左右件和若干姿态几乎同分的案例 |
| 缩放掩盖规格差 | 形状归一后同系列件很接近，实际孔径、螺纹或外廓不符 | 粗排可以利用比例，替代判断逐项按真实毫米值核对。测试规格相近件及英寸与毫米换算 |
| 不同 CAD 的几何表达 | 相同曲面被拆成几片，圆柱转样条，几何形状近似但面数变化。也可能因开壳或外部引用缺失导致特征缺失 | 面数和原始拓扑只作提示。验证跨 CAD 重新导出，检查导入诊断及共轴面合并，不能确定的特征保留未知 |
| 对齐或采样制造假结果 | 一个初始姿态陷入局部最优，或网格太粗使孔槽消失。程序计算精度也可能压过允许偏差 | 用基准约束、多初值、双向距离与关键区测量。用同件不同位姿、薄壁小孔与容差边界样本检查稳定性 |
| 几何一致而工程条件变化 | 材料、载荷、配合公差、表面处理或质量状态变了，模型外形几乎没变 | 逐项对照本次要求和旧版本证明，构造同形异材、旧版试验条件不足、图纸变更等反例 |
| 检索和版本排序遗漏 | 一个零件的多次导出挤占名额，或正确几何对应的可用版本被较旧的版本掩盖 | 按几何分组并展开版本。分别统计粗排未找回、精排掉出和版本不合格三类原因 |
| 只有模型，没有功能定义 | STEP 无法从形状本身告诉系统哪个孔是定位孔、哪个偏差对当前项目无关紧要 | 与客户确定产品族的功能接口清单，从图纸、PMI、装配关系或工程师标注补齐。关键项无法定位时待核定 |

## 4. 检索、比对与采用流程

1. **建库校验。** 用 OCCT 读取 STEP，记录原单位并统一到毫米，检查实体和引用完整性。缓存实际尺寸、无量纲比例、面积和适用的体积等特征。相同文件可共享几何计算，料号和修订独立保存。关键尺寸缺单位或模型不完整时，保留候选和异常原因，后续等待核定。
2. **三路粗排。** 按实际尺寸与体量、无量纲形状、需求单接口三路独立检索后取并集。接口一路按与平移、旋转无关的描述查找，例如孔径多重集、孔中心两两距离和最小体积有向包围盒的三边排序尺寸。这样可保留接口相同、加强筋或减重槽不同的候选。距离和边长在镜像后也可能相同。有可靠左右手标识时分别记录，未知时保留镜像歧义，待第 3、4 步按工程基准验证相对孔位、手性和净空。无法识别孔组或包络时记接口路缺项，仍可经尺寸路、形状路找回。用已知可替代案例和形似反例调候选数 K，联合考察漏检和耗时。建库及增量更新时缓存几何分组。仅当原尺度几何、手性和关键特征的一致性已验证时，重导出件才并组。仅从查询时可见且有权限的成员中选代表件并展示版本，按组占用前五名额。
3. **刚体对齐与几何精排。** 按需求单核实 AP242 基准 PMI、图纸或工程师标注，再用已确认的装配基准对齐。缺基准时用质心、主轴或特征生成多组初值，必要时用全局配准初始化和 ICP 精化。实际替代比较仅允许旋转和平移。镜像和缩放可帮助找到相关候选，报告保留其原始手性和真实尺寸。多个姿态近似、但关键孔映射不一致时，保留歧义并提交核定。仅靠最佳拟合获得的姿态可用于排序。必查接口的基准无法确认时，单列待复核区并记录原因，该区不计入前五命中。
4. **表面差异和关键特征验证。** 在同一工程基准下计算双向距离、分位值和容差覆盖率。对已确认闭合、可辨内外的实体，以新模型为参照，分别定位旧件多料和缺料的区域，在图上分别标正、负，按区域报告最大凸出量、最大缺料深度及其位置。开壳、朝向不明确或数值精度不足时标明符号或边界不确定。凡检出的凸出区域均查相邻件或约束包络的净空；缺包络且无相邻件证据时，候选至少待核定。已确认干涉且违反需求单限值时拒绝。缺料区逐项核对功能面、壁厚及载荷依据。关键孔、基准面、壁厚等从原始边界表示几何（B-rep）或受控图纸核对。网格离散与测量误差需明显小于工程容差并经样本验证，临界量无法确定时待核定。对关键特征输出参考基准、旧件实测、新任务要求、限值、结果和数据来源。
5. **采用判断。** 先检查 3D 对齐和几何数据的可信度，再核对需求单的硬条件及拟采用版本。建议采用的 STEP 必须是该料号该修订实际参加本次比对的几何，并已与该修订受控图纸核对一致。报告绑定文件摘要、发布标识和图纸及资料修订。只比较过 B 版时，若拟用 C 版，须取 C 版受控几何重新核对和比对，证据不足标待核定。明确有硬条件未通过时，建议拒绝采用并列出原因。缺少必查证据，或误差与限差重叠时，标为待核定。全部必查项得到有效证据支持后，输出建议使用的旧件版本及其已批准资料。工程负责人确认采用后，记录被替代的新设计、采纳的料号/修订、适用工况、证据与批准记录。登记新产品或项目中的实际使用位置、使用方及通知联系人。后续该料号有变更或撤回时，通知新使用方评估影响。

首期每个产品族只配置经工程负责人确认的判据。排名可从实际尺寸差、双向覆盖率和局部差异起步，经验证集调权重。所有关键阈值按图纸基准、尺寸公差或功能允许区间设置，平均偏差、综合分和检索名次均不能覆盖关键项的超限或证据缺口。

## 5. 交付与盲测验收

**交付。** 一次查询交付已确认的需求单、前五组候选及具体版本、差异图、逐项判据、三档采用结论及理由。人工复核区另列。负责人确认采用后，登记新使用关系，工程使用已核实的同一修订及配套成熟资料。

**版本关联抽查。** 阶段 1 核对全部已标注正例，再从其余库记录随机抽取至少 30 条。沿料号和修订核对实际 STEP、受控图纸及成熟资料，按正例组和随机组分别报告完整正确的链数 / 抽查总数，列明错版、过时和无法证实的记录。无法核实的链保留在分母中。未达客户预定门槛时先清理，重新抽样核验。

**历史需求单的来源。** 标记每份需求单为「当时成文」或「事后补写」。补写仅依据任务发生时已有的任务书、新件当时的图纸、相邻件修订等材料，逐项记录来源、版本和日期，并注明实际补写日期。选用不知道当年最终采用结果的工程师补写，对其屏蔽最终旧件和替代记录；补写人与该查询的标签评定人分开。缺乏同期依据的要求登记为待补。阶段 1 在接触系统输出前登记因来源不足只能作为参考的案例及原因，再核定可用盲测样本数。

**盲测冻结。** 在看到本系统及对照算法的输出之前，两名工程师依据历史替代记录和独立查档结果标注具体版本及理由，分歧由负责人裁定。每个查询的需求单、标签和当时可用的库快照同时冻结，专家和系统使用同一份需求单。按原件及派生版本划分调参与盲测集。盲测后新发现的候选按原需求单独立裁定，单报发现数及复核结果。冻结的正例集合和召回分母保持原口径。盲测期间发现遗漏，只登记为「需求缺陷」，注明引出问题的系统输出、原条款和拟修订内容。主指标一律按冻结版需求单计算，修订版可在盲测结束后单列复测。正确建议采用率、待核定率与误推荐率均按「当时成文」「事后补写」分别报告分子、分母与区间。历史记录偏向过去找到的旧件，报告应注明标签来源。

**样本与门槛。** 建议至少 60 个确有可用旧件的真实查询、20 个确无可用旧件的查询。关键特征超限、镜像不兼容、同形异材且材料不符、旧版验证条件不足、图纸变更导致不符、几何修订不一致这六类困难反例各至少 5 个，另外覆盖容差边界和新增特征。人工构造样例单列，不拼入真实查询率。盲测前由客户按误用代价签认误推荐率可接受的上界、正例待核定率上限、正确建议采用率下限及其数值判定方式。样本不足以支撑约定上界或各类下限时，仅报告可行性和补样量。

**从风险上界反推样本量。** 若真实盲测中观察到零次误推荐，要使 95% 单侧上界达到签认目标 p，产生采用建议的独立查询数至少为 `n = ⌈ln(0.05) / ln(1−p)⌉`。按正例产生建议的预计比例 r 规划，计划正例数取 `max(60, ⌈n/r⌉)`。另行满足无可用旧件查询和困难反例的样本下限。

| 目标风险上界 p | 至少需要的独立建议查询数 n | r 为 50% 时计划正例数 | r 为 70% 时计划正例数 |
| --- | ---: | ---: | ---: |
| 10% | 29 | 60 | 60 |
| 5% | 59 | 118 | 85 |
| 3% | 99 | 198 | 142 |
| 1% | 299 | 598 | 428 |

例如，60 个正例按 50% 建议率预计只有 30 个建议查询。若全组实际只有这 30 个独立查询得到建议且零误推荐，可报告的上界约为 9.5%。规划时同时签认目标 p、预计建议率及其依据、对应正例下限。若正例收集受限，事先列出可取得的正例数、预计建议数与该数量可支撑的零错误上界。验收使用全部盲测中实际产生建议的独立查询数和观察到的错误数。

**查询结论归类。** 分别对冻结的「存在可用旧件」和「无可用旧件」两组按下表从上到下判定，首次满足即归类。候选的工程结论与查询的统计类别分别保存。采用建议按冻结需求单逐项评定。若涉及原先未标注的版本，先由独立评定人补判其推荐是否正确，再归类。原先已冻结的查询分组、检索正例和分母仍用于计算找回率。

| 次序 | 类别 | 条件 |
| ---: | --- | --- |
| 1 | 正确建议采用 | 至少建议一个按冻结需求单验证合格的版本。同次有错误推荐时，该查询仍归此类，并另计一次误推荐。 |
| 2 | 仅错误建议 | 有采用建议，推荐的版本均已确认不合格或缺少采用所必需的证据。 |
| 3 | 待核定 | 没有采用建议，前五中至少一个候选结论为待核定。 |
| 4 | 仅在待复核区 | 前三类均未命中，尚需检查的候选仅在前五之外的待复核区。前五另有已拒绝版本时也归此类。 |
| 5 | 全部拒绝 | 有候选，全部明确拒绝，待复核区为空。 |
| 6 | 无候选 | 查询解析成功，前五和待复核区均为空。 |
| 7 | 解析失败 | 查询文件解析失败，未形成可比较结果。库侧记录失败另记漏检原因。 |

每组七类计数之和须等于该组冻结查询数。在原标为无可用旧件的查询组中，另报「出现任何采用建议」的冻结口径误报数。若其中确实发现合格旧件，注明漏标，在该组查询结论中归入第 1 类，并单列复核前后差异。风险上界按逐项核实的错误及缺证推荐计算；补判结果只用于判断推荐对错，冻结的检索命中及分母不回填。

| 指标 | 判定及分母 |
| --- | --- |
| 检索找回 | 在全部存在可用旧件的冻结查询中，报告粗排前 K 与前五几何组各有多少查询至少找回一个合格版本。另报前五找回的冻结合格「查询、版本」对数 / 全部冻结合格对数。查询解析失败、库侧不可检索和仅进待复核区的正例均保留在分母中。 |
| 接口检索贡献 | 对「非功能区域不同、接口合格」的正例，比较使用与停用接口路时的粗排漏失数及样本总数，查明非功能差异所致漏失。只有难例覆盖充分且停用后无新增漏失时，才评估能否简化。 |
| 正确采用与待核定 | 以全部存在可用旧件的冻结查询为分母，分别取分类表第 1 类及第 3 类的占比，对照客户签认的下限和上限。另列第 3、4 类合计占比，显示总人工核查负担。 |
| 误推荐与困难反例 | 每个已签认困难反例都必须拦截「建议采用」，按需求单逐例核对该拒绝还是待核定。按候选版本分别报告确认不合格和证据不足却被推荐的数量。对无可用旧件的查询另报出现任一采用建议的查询占比。 |
| 误采用风险上界 | 以产生采用建议的独立真实查询为单位。同一查询推荐多版，其中任何一版不合格或缺少必需证据，该查询计一次误推荐。对有 n 个此类独立查询、其中 0 次误推荐的情况，95% 单侧二项上界为 1 − 0.05^(1/n)。30 次约为 9.5%，60 次约为 4.9%。出现错误使用实际计数计算单侧精确上界。n 为零则无法估计；关联的派生查询按原件分组处理，不把重复版本凑入独立样本量。 |
| 业务结果 | 登记确认采用的具体修订、新使用位置、人工耗时和返工。试点期间的真实采用数只作观察。平台收益另按历史频次与人工对照估算。 |

各比例报告分子、分母及区间。人工确认后实际发生的误采用事件单独记录，便于区分系统建议和最终工程决定。

**人工核查量的签认。** 阶段 1 同时记录两类需要人工工作的正例查询：第 3 类「待核定」和第 4 类「仅在待复核区」。以冻结的正例查询总数为分母，两类互斥计数相加。具体上限待客户签认，可在第 3 类上限之外增设合计上限，或直接采用合计上限。

## 6. 内网平台的启动条件

阶段 1 统计每月适用的新设计数、历史替代率（同期可比任务中实际替代数 / 适用任务数）、查档人数、人工耗时和维护量。两项频次数据相乘得到每月预计替代机会。阶段 3 至少安排 10 组难度相当的配对任务，以相同需求比较现行人工方式与离线工具的净节时，包括失败返工。按平台相对离线工具**新增覆盖的机会或新增协作节时**折算收益，扣除月度维护成本。历史替代率、正确推荐比例和平均节时使用同一分母口径，避免重复计算成功率。保守情景取正确推荐比例区间下限及净节时的区间下限或较差四分位数，说明采用的假设。阶段 3 验收达标、有多人需求、维护人落实、保守月净增量收益为正且一次性投资能在客户签认期限内收回时启动平台。

## 7. 阶段计划及交付条件

| 阶段 | 估算与交付 | 放行条件 |
| --- | --- | --- |
| 1. 定场景与定标 | 约 2–3 周。试填需求单，形成关键接口清单，核验几何与图纸、成熟资料的版本关联，收集真实案例及平台频次。试补历史需求单、登记时点来源，独立标注并冻结需求单、库快照和标签 | 工程负责人能确认真实查询需求，版本链抽查通过客户门槛，盲测样本和困难反例达到下限，按目标风险上界和预计建议率签认正例下限与效用门槛。风险上界目标低于 10% 时按所需正例量重估本阶段工期。样本不足时说明可验证上界并转为可行性评估 |
| 2. 离线原型 | 约 3–4 周。实现预分组、含姿态无关接口特征的三路粗排、基准配准、带符号差异及凸出区检查，生成版本级对比报告 | 用验证集检查同件旋转、镜像、近规格、孔位移动及内部变化，核对有无接口路的差异和测量误差。规则、配额和参数冻结后进入盲测 |
| 3. 接入资料与盲测 | 约 2–3 周。交付使用关系记录、困难反例逐例清单、盲测报告及至少 10 组任务的人工对照 | 逐例拦截通过，正确建议率、待核定率和风险上界达到预签口径，能追溯采用版本并通知新使用方。未达到时记录缺口、补样或修正后用独立样本再测 |
| 4. 可选内网平台 | 约 3–5 周，沿用离线引擎，提供多人查询、证据核定、权限和采用记录查询 | 阶段 3 达标并满足第 6 节列出的启动条件。交付时核对离线结果一致性、权限隔离及使用关系追溯 |

以上为单零件族、资料可读且工程负责人能参与的日历时间估算。按基础排期，前三阶段合计约 7–10 周。更低风险上界所需的追加采样时间另计。资料清理、补样或新增系统接口的投入在阶段 1 重估。

首期范围止于一个零件族的离线替代判断和人工确认。整装配等效判定、批量自动切换生产版本、向客户 PDM 自动写回使用关系、其他业务系统写回和字段级迁移均需另行定范围和验收。

## 8. 启动前提与待核实事项

阶段 1 优先查明三项前提。第一，提交工程师能否写出由负责人确认的替代需求单。第二，能否取得任务发生时已有的任务书、图纸和相邻件资料，据此清点能用于盲测的正例。第三，客户签认的误推荐风险上界和有可用旧件时的预计建议率是多少，据此反推独立查询量及采样工期。同时按第 5 节商定人工核查合计上限。

| 需要客户明确或提供 | 影响 |
| --- | --- |
| 「直接用老模型」的实际应用场景，例如装配替代、重新生产或沿用已批准工艺 | 决定哪些要求是硬条件、需要核查哪些成熟数据 |
| 历史上已直接替代的真实案例，以及看起来接近但曾经不能采用或误采用的案例 | 定义标签，验证检索覆盖、误推荐及边界行为 |
| 首个产品族、关键基准、接口和公差、材料与工况证据、装配限制 | 建立量测和采用规则，决定项目需要补充哪些源资料 |
| STEP 是否含 PMI、零件与装配比例、不同 CAD 来源与资料版本映射质量 | 确定自动核对覆盖率、人工核定工作量和试点工期 |
| 可接受的误推荐风险、人工核定比例和样本规模 | 签认验收条件，确定从试点进入实际工程使用的门槛 |
| 新设计阶段能否提供可确认的需求、相邻件或约束包络 | 用 3–5 个真实任务试填需求单。关键项填不全、凸出区缺净空证据时，估算待核定比例并评估试点价值 |
| AP242 基准 PMI 是否存在且能对应到特征 | 分导出器抽检，以图纸及工程师确认的基准交叉核对 |
| 现有变更流程能否通知新使用位置 | 用一次历史变更回放从料号到新项目责任人的通知路径，明确维护人和补录方式 |
| 能否取得当年设计时点的任务书、图纸与相邻件资料 | 试补 3–5 个历史案例，统计能注明同期来源的条目比例，据此确定可纳入盲测的正例数 |
| 逐查询核对拟采用修订的几何与受控图纸需要多少人工 | 阶段 1 试填时按候选计时，记录缺证据数，据此估算人工核定负担 |

## 技术依据

- OCCT 提供 STEP 几何、拓扑和装配结构的读取，XDE 可读取模型携带的部分附加属性。客户文件能否提供所需 PMI、装配基准或材料要抽查确认。[OCCT STEP 导入指南](https://dev.opencascade.org/doc/overview/html/occt_user_guides__step.html)
- Open3D 的 ICP 以初始变换为输入，并给出配准内点比例和残差等度量。产品族依赖的功能基准、特征对应与替代规则需另行验证。[Open3D ICP 配准](https://www.open3d.org/docs/release/tutorial/t_pipelines/t_icp_registration.html)

当前尚无客户样本实测，文中的门槛算例及排期用于试点规划。
