## 遗漏

**S4-1 上界剪枝须按重分配后有效权重计算，并区分“精确剪枝终止”与“上限 $K$ 截断”**
- **影响**：动态百分比检索防漏检机制、阶段 2 精排引擎实现、验收找回分母归因。
- **最小修正**：在提案第 2.3 节明确：每对 `(query, m)` 先确定有效维度集合 $V(m)$ 及重分配后的有效权重 $W'_i(m)$，再按 $U(m) = \sum_{i \in V(m)\setminus\{\text{D5}\}} \frac{W'_i(m)}{100}s_i(m) + W'_{\text{D5}}(m)$ 降序遍历进入精排；仅当剩余候选中最大 $U(m) \le S_{(5)}$ 时为无漏检精确终止；若因并发耗时预算触发精排上限 $K$ 提前终止，须在查询诊断日志中标记“达到精排上限截断”，且在验收检索找回统计中将由此导致的漏检归入“粗排/预算截断漏出”并保留在分母中。

**S4-2 维度池中“孔系特征”归属在提案与说明文档间不统一，且“缺项重分配”缺少单方缺失语义与全项缺失除零保护**
- **问题细节**：
  1. `PROPOSAL.md` 第 1 节只有 D1–D7（孔系特征仅作为 D3 无 PMI 时的降级替代），但 `STATUS.md` 与 `Docs/STEP模型相似度评判逻辑与判断标准说明.md` 第 3.1 节将“局部关键几何特征拓扑（孔系）”列为独立补充标准 3（建议占比 10%），而该文档第 3.2 节配比表又只列了 6 行、将其并回第 3 项。客户阅读时会混淆“孔系特征”究竟能否独立设权重。
  2. 提案将“单/双方缺失材料或非几何属性”一并做权重重分配，但**双方均缺失**与**单方缺失**（如新件明确要求特定材料或 PMI 公差，旧件未填）工程含义不同——单方缺失若直接抹除该项权重，会让“未填材料的未知旧件”得分高于“填了近似材料的旧件”并掩盖核对风险。
  3. 当管理员将所有必有几何项权重设为 `0%`（仅启用 D1/D3）且某对模型 D1、D3 均缺失时，有效维度集合 $V = \emptyset$，归一化公式 $W'_i = W_i / \sum_{j\in V} W_j$ 会出现 `0/0` 除零异常。
- **影响**：评分规则引擎数据模型、`Docs/STEP模型相似度评判逻辑与判断标准说明.md` 对客口径、规则保存校验逻辑。

  2. 区分“双方缺失”与“单方缺失”：双方缺失默认可按规则重分配或走几何替代；单方缺失须在评分详情显式标出「单方缺失（未核实）」，并由规则配置显式选择“按 0 分/中性分/重分配”之一，不默认静默抹除。
  3. 规则引擎补齐除零保护：保存规则时校验（或运行时兜底）——当有效维度集合 $V = \emptyset$ 时禁止除零，标记该候选为「特征不足/待复核」并在详情注明原因。

**S4-3 无邀请码 5 次限额存在并发穿透漏洞，客户端双 API 缺少鉴权传输规范、畸形文件隔离熔断与异步解析失败状态**
- **问题细节**：
  1. **5 次限额并发穿透**：提案第 3 节 2-1 规定“仅当成功解析并返回对比结果时扣 1 次”，但单次 STEP 解析与 ICP 对比耗时数秒。若在比对完成后再扣减，并发发起多笔请求会全部通过 `< 5` 校验并耗尽算力；若全程持数据库行锁，又会阻塞连接池。
  2. **客户端密码传参安全与防暴力破解**：2-6/2-7 要求支持用户名和密码调用，未明确禁止通过 URL Query 传明文密码（会落入代理/访问日志），也未约定密码错误频次锁定与日志脱敏。
  3. **畸形 STEP 计算 DoS 防护**：防刷不能只靠“文件大小上限 + 人工确认”，2-7 对比接口是实时解析用户上传的 `.stp` 的，极小体积的畸形 STEP 也可能导致 OCCT 内存飙升或死循环；同时无邀请码账号若无注册频率/验证码限制，可通过批量注册新号绕过 5 次配额。
  4. **待审通过后异步解析失败与重复 MD5 处置缺失**：2-6 流程中模型仅有 `PENDING / APPROVED / REJECTED` 三态，缺少审核通过后后台 OCCT 解析失败时的 **`PARSE_FAILED` 状态**（否则损坏件会被误标 `APPROVED` 或永久卡在 `PENDING`）；也未说明客户端批量上传命中本企业已有 `APPROVED` 或 `PENDING` 相同 MD5 时的处理规则。
  5. **审核角色归属与页面工程边界提示**：未明确 `PENDING` 队列仅由平台“系统管理员”审核还是各企业可设“企业管理员”自审；服务端图形化对比工作台验收项未沿用 `STEP-SIM-003` S3-1 的固定边界说明（提示相似度排序不单独等同于工程直接替代放行）。
- **影响**：模块二权限/审核状态机、模块三客户端双 API 与 Web 工作台、安全与并发验收能否通过。
- **最小修正**：
  1. 5 次限额改为**“入口短事务预占（`used + in_flight < 5` 校验并 `in_flight += 1`）→ 解析/比对成功转实扣（`used += 1, in_flight -= 1`）→ 损坏或服务端异常回滚释放（`in_flight -= 1`）”**。
  2. 明确客户端 API 严禁在 URL Query 传递密码（仅限 HTTPS Body 或 Header，推荐先换取短期 Token），强制日志脱敏与失败退避锁定；OCCT 解析/网格化运行在独立工作进程并配置**单件解析超时与内存/最大面片熔断上限**；注册入口防刷策略（IP 限流/图形验证码或关闭自助注册开关）写入方案或「未核实」待阶段 1 确认。
  3. 入库状态机补充 `PARSE_FAILED`（记录失败诊断并禁止进入检索池，计入导入失败统计），明确批量上传命中企业内重复 MD5 时的提示/去重策略；在「未核实」补充“待审队列由平台管理员统一审还是增设企业管理员分审”；在 Web 工作台与验收条款补上固定工程边界提示。
