# Rules.md — STEP 模型相似度对比检索平台与旧件复用项目规则

## 1. 项目记忆文件

| 文件 | 用途 | 读取时机 |
| --- | --- | --- |
| .claude/SessionBrief.md | 当前目标、已定口径、未决事项和下一步；保持简洁 | 每次开始项目任务时 |
| .claude/Plan.md | 仍待推进的 1–3 项工作及其状态 | 每次开始项目任务时 |
| .claude/ProjectMemory.md | 跨模块长期有效的项目共识、边界和稳定约束 | 每次开始项目任务时 |
| .claude/contexts/00-index.md | 模块记忆目录、模块边界和按任务选择的入口 | 每次开始项目任务时；再按任务读取相关模块文件 |
| PlanDocs/ | 提案、独立审核、采纳决定及讨论归档 | 用户要求处理 PlanDocs；或讨论方案、验收口径、阶段顺序时；若 STATUS 不是 IDLE，先按 README 读取当前轮材料 |
| Docs/ | 当前正式平台详细开发设计文档与详细开发计划、对客标准说明与报价单；以及 STEP-SIM-002 原基线实施方案与客户汇报材料（暂不覆写） | 编辑、审阅或汇报方案时 |
| .claude/contexts/<模块>.md | 单个模块的当前设计、未决问题、证据和入口 | 处理该模块时读取；不要整目录加载 |
| 归档文件 | 已结束工作的历史记录 | 需要追溯时 |

模块记忆按实际工作创建和维护，不预先堆砌空白文件。聊天内容不作为长期项目记忆。

## 2. 项目任务开始时

1. 从当前目录向上查找最近的 .claude/Rules.md，读取后遵守。若找不到，明确告知用户；不要声称读过项目记忆。
2. 读取本项目的 .claude/SessionBrief.md、.claude/Plan.md、.claude/ProjectMemory.md 和 .claude/contexts/00-index.md。根据任务从索引选择相关模块记忆，不要默认全文加载 contexts/ 或其他历史材料。
3. 触及方案范围、判断口径、实施顺序或验收规则时，先以 PlanDocs/README.md 为交接规范。若 PlanDocs/STATUS.md 非 IDLE，读取 README、STATUS 和当前轮 PROPOSAL/REVIEW；按当前角色与状态处理。
4. 直接引用已采纳决定前，核对 PlanDocs/DECISIONS.md。STEP-SIM-004 是当前业务口径；其归档审核和提案位于 PlanDocs/STEP-SIM-004/。STEP-SIM-002 及更早决定只按下文第 3 节所述范围沿用。

## 3. 当前项目的事实来源和决策顺序

- 用户最新明确指令优先；已采纳决定记录在 PlanDocs/DECISIONS.md。正式平台实施细节以 Docs/STEP模型相似度对比与检索系统详细开发设计文档.md 和 Docs/STEP模型相似度对比与检索系统详细开发计划.md 为当前基线；Docs/STEP模型相似度评判逻辑与判断标准说明.md 和报价单 Excel 是对客衍生材料，修改后需核对与基线口径一致。
- 当前主目标（STEP-SIM-004）：交付多企业 STEP 相似度对比与检索服务平台，包括可配置 D1–D7 权重与独立安全门禁、多企业隔离、无邀请码 5 次限额、五态人工审核入库、Web 三维对比工作台和客户端双 API。相似度分数只用于检索、排序和差异辅助检查，不能单独等同于工程替代放行；Web 工作台须固定展示工程边界提示，最终采用由工程负责人确认。
- STEP-SIM-002（旧件修订直接替代）不再是本平台建设的前置阻塞：替代需求单、三档自动替代判定、60 正例历史盲测和平台回收期前置测算，只在客户未来要求叠加“自动给出旧件替代放行建议”时补齐。STEP-SIM-002 原基线实施方案与 PPT 暂不覆写，不要把它恢复为主目标。
- STEP-SIM-001 的字段复用主目标此前已被 STEP-SIM-002 部分替代，同样不恢复为主目标。
- 跨阶段底线：沿用 STEP-SIM-003 已验证的几何内核（毫米统一、24 初值右手系刚体配准、GLB 矩阵换算、对称歧义进待复核）；解析失败、`truncated_by_k` 截断与待复核均计入检索找回验收分母，不得静默跳过。
- 所有量化门槛、工期、报价分项、样本量和容量上限，在客户样本实测前均按建议值/规划值表述。区分客户原始要求、已采纳决定、外部可核实事实、待验证假设和实测结果。
- 阶段 1 的开放前提见 SessionBrief 和 DECISIONS 中 STEP-SIM-004 的未决假设：客户真实样本盘点，规则、安全、接口与部署环境契约冻结。讨论中的修正以 PlanDocs/STATUS.md 当前话题为准，采纳前不改变基线。

## 4. PlanDocs 交接约束

- PlanDocs/README.md 是提案和审核的操作规则。保留其话题编号、轮次、状态、标题和角色边界。
- 提案、审核、决定分别写入各自约定文件；提案方保留审核方原文，不代写独立审核结论。
- 只有用户明确确认收口时，才将讨论决定标记为 ADOPTED 并写入 DECISIONS.md；同时核对实施方案、汇报材料和归档路径。
- 不擅自改写 PlanDocs README 或已归档讨论。修正已采纳方案时，按用户要求更新基线，并在需要改变方向或验收口径时重新进入 PlanDocs 讨论。

## 5. 保存记忆与上下文整理

用户说“读取记忆”时：
1. 读取本文件、SessionBrief 和 Plan。
2. 按需查阅 DECISIONS、当前 Docs 或非 IDLE 的 PlanDocs 轮次。
3. 用中文汇总当前目标、已定口径、风险/前提、下一步；不整目录灌入历史材料。

用户说“保存记忆”或一项已确认工作完成时：
1. 刷新 SessionBrief：只记当前仍有效的状态、已定口径、未决前提、最近变更索引和下一步。
2. 刷新 Plan：只保留 1–3 项未完成工作；完成项移除或归档，不把历史过程堆在当前计划里。
3. 把跨模块稳定共识写入 ProjectMemory；把模块专属的当前设计、证据、风险和下一步写入对应 contexts 文件，并更新 contexts/00-index.md 的链接或状态。不要把模块细节重复堆进 ProjectMemory。
4. 方案决定的完整历史留在 PlanDocs；不要在记忆文件重复粘贴长方案。
5. 项目记忆只写在本项目 .claude/ 下，不写入系统级记忆、个人 Claude 项目记忆或 save-session。

## 6. 内容质量与工具使用

- 保持独立判断：发现需求与证据冲突、样本偏差、漏检风险或未经验证的结论时，说明依据和影响，不把假设写成事实。
- 引用技术标准、CAD 内核能力、第三方库特性或随时间变化的资料时，核对可靠来源；不能核实时明确标注待验证。
- 正式平台代码在 `Platform/` 目录、`feat/platform-v1` 分支下开发，不改动 `Demo/`。代码审查、测试与分支合并约定待 STEP-SIM-005 定稿后补入本规则；在此之前，用户未要求时不擅自扩展代码实现，也不预设本项目必须有 CRDocs。
- 不复制来源项目的 Si_FastSuite/OLP 架构约束、固定模型协作工具、报价模板、脚本语言限制或单文件行数门槛；除非本项目后来出现同类需求并由用户确认适用。
- 本项目默认中文沟通。文件命名及项目已有格式优先沿用现状。
