## 阶段 1：客户样本盘点与安全/接口/规则契约冻结（约 1.5–2 周）

**目标**：拿真实数据摸底，把所有可能返工的边界参数一次签认冻结。

- [ ] **1.1 客户真实样本盘点脚本与体检报告**
  - 抽取客户 20–50 件代表性 `.stp`/`.step`，运行 `STEPCAFControl_Reader` 统计：AP203/214 vs AP242 分布、PMI 携带率、材料与属性填写率、单/多闭合实体与开壳/装配体占比、单文件体积与面片数分布、跨 CAD 重导出面片分裂实测。
- [ ] **1.2 规则与安全契约签认冻结**
  - 签认 `D1–D7` 默认百分比模板、零分阈值及**单方缺失默认策略**（默认 `ZERO` 保守计分）；
  - 签认**待审队列审核角色粒度**（全局系统管理员 vs 增设企业管理员）；
  - 签认**无邀请码注册防刷方式**（IP 限流 + 图形验证码 + 后台开关）及公共演示库样本来源；
  - 签认规则作用域（全局唯一 vs 按企业覆盖）。
- [ ] **1.3 客户端 API 与部署环境冻结**
  - 确认客户端调用形态、峰值并发、Top-1/Top-N 返回结构、同步/异步模式及选中次数回传契约；
  - 冻结单文件上限（如 `50 MB`）、精排上限 $K$（如 `50`）、OCCT 硬超时（如 `60s`）、内存/面片熔断上限及预占超时回收阈值（强制 `> 排队上限 + OCCT 硬超时`）；
  - 获取目标服务器环境清单（OS、CPU/内存、磁盘、HTTPS 证书）。
- [ ] **阶段 1 放行条件**：真实样本盘点报告输出，上述参数与契约经客户书面/纪要确认冻结。

## 阶段 2：多维特征引擎与动态有效权重评分内核（约 3.5–4 周 · 对应报价模块一 37 人/天）

**目录**：`Platform/backend/app/geometry_engine/`、`Platform/backend/app/rules/`、`Platform/backend/app/compare/`

- [ ] **2.1 工程脚手架与独立 OCCT Worker 子进程（5 人/天）**
  - 搭建 `Platform/backend/` FastAPI + SQLAlchemy + Alembic 骨架；
  - 实现 `worker_runner.py`：文件头 `ISO-10303-21;` 校验、独立进程隔离执行、单件硬超时强杀、内存与最大面片数熔断、异常崩溃自动拉起与标准化错误码。
- [ ] **2.2 `D1–D7` 全维度特征提取与持久化（10 人/天）**
  - `step_reader.py`：复用 `Demo/src/geometry.py` 毫米统一，扩展单闭合实体/多闭合实体累加/开壳显式标记；
  - `features_d1_d4.py`：D1（名称词干 + XDE 属性/颜色/图层 + 材料 + B-Rep 参数）、D2（有效闭合体积）、D3（`XCAFDoc_DimTolTool` AP242 PMI 解析）、D4（总表面积 + `BRepAdaptor_Surface` 类型面积占比 + 共轴/共面逻辑合并有效面数）；
  - `features_d6_d7.py`：D6（主轴 OBB 尺寸与比例）、D7（内圆柱孔识别、孔数、孔径多重集、孔心距分布）；
  - 序列化版本化 `feature_payload`（`feature_version`）并导出轻量化采样点云与 GLB 缓存。
- [ ] **2.3 空间刚体对齐、双向表面偏差与安全门禁（13 人/天）**
  - `alignment_d5.py`：复用并工程化封装 24 初值右手系刚体配准、Trimmed ICP（点到面 + SVD 回退）、AABB 树双向 RMS/P95/Max 采样及 $C_{\text{新}} T C_{\text{旧}}^{-1}$ 矩阵换算；
  - 安全门禁：确保去重容差严格紧于歧义阈值，右手系暴露镜像偏差，多合格姿态歧义自动标「待复核」。
- [ ] **2.4 动态百分比打分器、缺项规则与有效权重上界剪枝（9 人/天）**
  - 实现 `D1–D7` 百分制子分、总和 `100%` 校验、双方缺失重分配/D3 转 D7 替代、单方缺失显式标记与三选一策略、$V(q,m)=\emptyset$ 防除零转「特征不足/待复核」；
  - 实现基于重分配有效权重 $W'_{\text{D5}}(q,m)$ 的上界剪枝 $U(q,m) = S_{\text{other}}(q,m) + W'_{\text{D5}}(q,m)$，精确区分 `exact_pruned` 与 `truncated_by_k` 诊断标记。
- [ ] **阶段 2 放行条件**：修改任意权重免重解析生效；数学一致性（误差 `< 0.05`）、$V=\emptyset$ 兜底、有效权重上界无误剪单测及四类难例（面片分裂/无 PMI/同体异形/镜像对称）回归测试全部通过。

## 阶段 3：多企业权限、五态待审台账与服务端规则后台（约 3–3.5 周 · 对应报价模块二 31 人/天，与阶段 2 中后段并行）

**目录**：`Platform/backend/app/db/`、`auth/`、`models_mgmt/` 及对应管理端页面

- [ ] **3.1 账号认证、企业邀请码与 5 次并发预占限额（11 人/天）**
  - 实现数据库表结构与 Alembic 迁移（`enterprises`, `invite_codes`, `users`, `trial_reservations`, `models`, `similarity_rules`, `compare_jobs`, `compare_results`, `audit_logs`）；
  - 实现注册（IP 限流 + 验证码 + 后台开关）、Argon2id/bcrypt 慢哈希、JWT 登录、连续失败退避锁定、企业管理与邀请码生成/绑定/补绑；
  - 实现无邀请码 5 次限额短事务原子预占（`used_count + in_flight_count < 5`）+ 成功实扣 + 损坏/异常回滚 + 超时回收器（`reaper_ttl > 排队上限 + OCCT 硬超时`）；
  - 封装 Repository 层 `apply_visibility_scope` 跨企业强制隔离守卫（涵盖列表/详情/GLB/对比全路径）。
- [ ] **3.2 模型台账管理、五态审核流与 MD5 幂等去重（13 人/天）**
  - 实现服务端批量上传与手动对比查询归档（查询件与模型库隔离）；
  - 实现 `PENDING → INDEXING → APPROVED / PARSE_FAILED` 及 `REJECTED` 五态状态机与隔离暂存区管理；
  - 实现同企业重复 MD5 幂等跳过（`APPROVED`/`PENDING`/`INDEXING`）与历史失败重提，确保跨企业零信息交叉；
  - 完整落库并展示 6 项必记字段（`md5码`、`模型名称`、`日期`、`上传人`、`模型特征值`、`对比选中次数`）及多条件检索。
- [ ] **3.3 服务端规则配置与管理后台（7 人/天）**
  - 开发可视化规则配置页（`D1–D7` 滑块/输入实时校验 `100%`、零分阈值、双/单方缺失策略、上限 $K$、多项目模板保存与一键生效、规则版本快照）；
  - 开发企业/邀请码/试用配额与审核日志管理页。
- [ ] **阶段 3 放行条件**：四角色越权矩阵测试 0 泄漏；10 路并发下 5 次限额无穿透且损坏件准确回滚；`PENDING` 与 `PARSE_FAILED` 检索命中为 0。
